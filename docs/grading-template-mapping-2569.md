## สิ่งที่แก้ในโค้ดแล้วในรอบนี้

- ลบการคืนคะแนน ป.1 ชุดตั้งต้นอัตโนมัติทั้งตอน `loadGrades` พบคะแนน 28/K15 และตอนโหลด Firebase ที่ยังไม่ได้ตั้งค่า
- เพิ่มเวลาการแก้รายช่อง `teacherKUpdatedAt`, `midtermExamUpdatedAt`, `finalExamUpdatedAt` เก็บไว้แม้ล้างค่า เพื่อแยกการล้างจริงจากข้อมูลที่ไม่ได้ส่งช่องนั้นมา
- การรวมข้อมูลไม่สร้างเวลาแก้ใหม่จากการอ่าน และไม่นำคะแนนเก่าที่ถูกล้างกลับมา การส่งคะแนนกิจกรรมรักษารุ่นการแก้ของครู
- รวมรายชื่อ local/remote ด้วยรหัสนักเรียน เก็บรายการที่มีเฉพาะฝั่งใดฝั่งหนึ่ง ไม่รวมคะแนนคนละรหัสเพียงเพราะชื่อหรือเลขที่ตรงกัน
- ยกเลิกการเดาจับคู่ progress จากเลขที่หรือชื่อบางส่วน สำหรับ progress รุ่นเก่าต้องตรงทั้งห้อง เลขที่ และชื่อ; รายการที่ไม่ตรงจะไม่ถูกเติมคะแนนอัตโนมัติ
- รวม K/P/A ก่อนปัดเศษยอดรวม: ตามนโยบายที่ครูยืนยัน ประถม K/P/A = 21/8.75/5.25 รวม 35; มัธยม = 33/13.75/8.25 รวม 55 (คงสัดส่วนภายใน K/P/A 60/25/15)
- CSV ใช้สัดส่วนจากค่ากลาง และเก็บช่องสอบว่างต่างจากคะแนนศูนย์
- ช่องสอบใช้ร่างระหว่างพิมพ์ บันทึกเมื่อ Enter/ออกจากช่อง และแจ้งคะแนนนอกช่วงโดยไม่บันทึกค่านั้น
- แก้ข้อความช่วยกรอก: ล้าง K หมายถึงกลับไปใช้คะแนนเว็บและงาน ส่วนล้างคะแนนสอบหมายถึงยังไม่กรอก

ครูยืนยันให้ใช้สัดส่วนตามแบบฟอร์มแล้ว: ประถม 35+15 ต่อเทอม มัธยม 55+15+30 ใช้ `getGradingPolicy` รุ่น `school-2569-v1` ร่วมกันในสมุดคะแนน รายงานนักเรียน CSV และหน้าพิมพ์

คะแนนสอบประถมเก่าไม่มี `finalExamMax` ถือเป็นเต็ม 30 ตามระบบเดิม คงคะแนนดิบไว้และเทียบเป็นเต็ม 15 ตอนคำนวณ/แสดงผล มีข้อความระบุคะแนนเดิมในสมุดคะแนน เมื่อกรอกใหม่จะบันทึกคะแนนพร้อม `finalExamMax=15` และรุ่นเกณฑ์ จึงไม่หารสองซ้ำ หากข้อมูลเก่าเคยถูกนำเข้าบนฐานคะแนนอื่น ต้องตรวจฐานคะแนนก่อนใช้รายงานจริง

ประถมเทอม 1 แสดง “รอผลทั้งปี”; มัธยมที่ขาดสอบหรือ K/P/A ที่ประเมินแล้วแสดง “คะแนนยังไม่ครบ”; ไม่นับสถานะเหล่านี้เป็นผ่าน/ไม่ผ่าน ส่งออกช่องสอบที่ไม่กรอกเป็นว่าง Master CSV ระบุคะแนนเต็ม ปี เทอม และรุ่นเกณฑ์ต่อแถว

ขณะนี้บริบทที่รองรับยังเป็นปี 2569 เทอม 1 ไม่มีตัวเลือกเทอม 2 หรือการรวมผลทั้งปีประถม การคำนวณยอดอาจเปลี่ยนตามเกณฑ์ใหม่ แต่ไม่ได้เขียนทับคะแนนดิบเดิมทั้งหมด

## ลำดับทำต่อ

1. **นโยบายรายวิชา — ทำแล้วสำหรับเทอม 1** ครูยืนยันสัดส่วนตามแบบฟอร์ม กำหนดปี/เทอม/รุ่นเกณฑ์ใน `gradingPolicy.ts` คำนวณสองตำแหน่งทศนิยม; งานต่อคือเลือกปี/เทอมและเก็บนโยบายย้อนหลังโดยไม่ปะปน
2. **ความปลอดภัยและการบันทึก** แยกข้อมูลผลงานนักเรียนออกจากคะแนนทางการ ย้ายผู้เขียนคะแนนไป Firebase Auth/บทบาทครูหรือบริการที่ตรวจหลักฐาน ก่อนจำกัด Firestore Rules; เพิ่มคิวบันทึกถาวร สถานะรอส่ง/ส่งแล้ว/ส่งไม่สำเร็จ และลองใหม่ ปัจจุบันยังไม่ได้แก้สองส่วนนี้
3. **ปี/เทอมและการย้ายข้อมูล** สำรอง legacy keys, ระบุว่าข้อมูลชุดเก่าเป็นปี/เทอมใด, ย้ายด้วยขั้นตอนตรวจซ้ำได้โดยไม่ทับข้อมูลเดิม; รองรับรายปีประถมแยกจากรายเทอมมัธยม
4. **ความครบและการรับรองผล** ใช้สถานะยังไม่ครบ/รอยืนยัน/ปิดผล; ไม่ให้รายงานทางการสรุปเกรดเมื่อขาดคะแนนหรือเทอม; ผลคุณลักษณะ สมรรถนะ อ่าน–คิด–เขียน ต้องมาจากแบบประเมินที่ครูยืนยัน มิใช่อนุมานจากยอดคะแนน
5. **จับคู่ข้อมูลและส่งออกแบบโรงเรียน** มีหน้าตรวจรายการไม่ตรงรหัส/ย้ายเข้าออกและประวัติการจับคู่; ตัวส่งออกเติมสำเนาแม่แบบตาม mapping ที่อนุมัติ พร้อมตรวจปี ชื่อวิชา ยอดรวม และรายการคะแนนไม่ครบ

ข้อควรระวังในการย้าย: progress รุ่นเก่าใช้ชื่อ/เลขที่เป็น ID จึงยังไม่สามารถรับรองการจับคู่ข้ามปีได้ทั้งหมด; เวลาการแก้รายช่องอาศัยนาฬิกาอุปกรณ์ ต้องเพิ่ม version ที่เซิร์ฟเวอร์ควบคุมและ UI จัดการความขัดแย้งก่อนรองรับครูหลายเครื่องแก้พร้อมกันอย่างเต็มรูปแบบ

- `persistentSaveQueue`: เก็บรายการแก้ K/P/A และสอบใน localStorage ก่อนส่ง เรียงส่งทีละรายการ รวมการแก้ช่องเดิม เก็บรายการเมื่อส่งล้มเหลว กดลองใหม่ได้หลังเปิดหน้าอีกครั้ง ไม่ลบการแก้ใหม่เมื่อคำตอบของรายการเก่ากลับมา และไม่เขียนทับคิวที่อีกแท็บเปลี่ยน
- หน้าสมุดคะแนนแสดงกำลังบันทึก/บันทึกแล้ว/ส่งไม่สำเร็จ จำนวนรายการรอและข้อความผิดพลาด สถานะครอบคลุม **การแก้รายช่อง K/P/A และสอบ** ยังไม่ครอบคลุม manual assessments การนำเข้าทั้งห้อง และการสร้าง/คืนค่าชุดข้อมูล
- หาก storage เต็มหรือหลายแท็บขัดแย้ง คิวแสดงข้อผิดพลาดและหยุดส่ง ต้องเปิดหน้าที่ยังกรอกไว้และสำรองข้อมูล การประสานการแก้จากหลายแท็บแบบอัตโนมัติยังไม่รองรับ

### ขอบเขตการตรวจและก่อน deploy

ทดสอบด้วย mock Firebase และ queue tests ไม่ใช่การรับรองกฎจริงบน Firebase: เครื่องนี้ไม่มี Java, firebase-tools หรือ rules-unit-testing จึงยังไม่ได้รัน Firestore Emulator และ **ยังไม่ได้ deploy Rules/เว็บไซต์**

ก่อน deploy ต้องตรวจบัญชีครู Firebase จริง ทดสอบ rules matrix (anonymous/student/viewer ปฏิเสธ, teacher/admin อนุญาต, inactive ปฏิเสธ, delete ปฏิเสธ) และเปิดโค้ดเกมเวอร์ชันใหม่ก่อนบังคับ Rules โค้ดเกมเก่าที่ยังค้างในแท็บจะต้อง reload

หน้ารายงานนักเรียน/ผู้ปกครองเดิมอ่าน grades ทั้งห้อง ซึ่งจะถูกกฎใหม่ปฏิเสธ ต้องทำข้อมูลผลรายบุคคลที่เผยแพร่แล้วและผูก Firebase UID กับรหัสนักเรียนโดยครู/เซิร์ฟเวอร์ก่อนเปิดการดูผลออนไลน์อย่างครบถ้วน **ห้าม deploy ชุดกฎนี้โดยข้ามงานดังกล่าว** ไม่อนุญาตให้ client อ้างรหัสนักเรียนแล้วอ่านคะแนนเอง

ข้อที่ยังเหลือ: เลือกปี/เทอมและย้ายข้อมูลเก่า, หน้าจับคู่รายการไม่ตรงรหัส, นำผลคุณลักษณะ/สมรรถนะ/อ่านคิดที่ครูยืนยันมาใช้จริง, workflow รอยืนยัน/ปิดผล, คิวสำหรับการแก้ชนิดอื่น และการรับรองผลรายบุคคลฝั่งเซิร์ฟเวอร์

- เพิ่มปุ่ม “ยืนยันผลเพื่อใช้ในรายงาน” ในหน้าแบบประเมิน ตรวจครบทั้งห้องก่อนยืนยัน การแก้ไขผลภายหลังยกเลิกการยืนยันเดิม และไม่เก็บสถานะยืนยันใน cache หากการส่งขึ้นคลาวด์ไม่สำเร็จ
- ช่องผลประเมินที่ยังไม่ยืนยันส่งออก CSV เป็นว่าง ในใบแจ้งผลแสดงยังไม่ประเมิน/รอยืนยัน คะแนน 0 แสดงไม่ผ่าน (แก้จากเดิมที่ตกไปเป็นผ่าน)
- SchoolMIS ตรวจผลการเรียนและแบบประเมินครบก่อนสร้างไฟล์ ส่วนไฟล์ตรวจสอบ CSV/Excel ยังคงดาวน์โหลดข้อมูลที่อยู่ระหว่างทำได้
- Rules ของ studentAssessments เปลี่ยนเป็นครูเท่านั้นใน repository ด้วย เพื่อไม่ให้ผลที่ใช้ยืนยันถูกเขียนจากบัญชีทั่วไป ทั้งนี้อยู่ภายใต้ข้อกำหนดก่อน deploy ด้านบน
- การส่งออกอ่านสำเนาแบบประเมินในเครื่องที่เปิดอยู่ ต้องใช้ปุ่มดึงจาก Firebase ในหน้าแบบประเมินเมื่อเปลี่ยนเครื่อง ยังไม่ได้สร้างระบบรับรองเอกสาร/ปิดผลบนเซิร์ฟเวอร์

งานที่ยังไม่เสร็จหลังรอบนี้: บริบทปี/เทอมย้อนหลังและเทอม 2, รวมผลทั้งปีประถม, จับคู่รายการรหัสไม่ตรง, คิวสำหรับการแก้ชนิดอื่น, ปิดผลพร้อมประวัติแก้ไขฝั่งเซิร์ฟเวอร์, ช่องทางดูผลรายบุคคลที่ตรวจสิทธิ์ และการทดสอบ/เปิดใช้ Rules จริง
