# ผลวิเคราะห์ระบบคะแนน — 22 กันยายน 2569

ขอบเขต: ตรวจโค้ดสมุดคะแนน การรวมข้อมูล การคำนวณ การส่งออก และกฎ Firestore ใน repository ปัจจุบัน พร้อมทดสอบฟังก์ชันคำนวณ/รวมข้อมูลด้วยข้อมูลจำลอง ไม่ได้อ่านหรือแก้คะแนนนักเรียนจริง และไม่ได้ยืนยันว่า Firestore Rules ที่ใช้งานจริงตรงกับไฟล์ใน repository

## อัปเดตหลังได้รับแบบฟอร์มงานวัดผล

รายการด้านล่างเป็นผลตรวจก่อนแก้ วันที่ 23 กันยายน 2569 ปิดงานใน repository ครบแล้ว: ยกเลิกการรีเซ็ตอัตโนมัติ, รักษาการล้าง K/สอบ, รวมรายชื่อด้วยรหัสนักเรียน, ใช้สูตรตามแบบฟอร์ม, แยกช่องว่างกับศูนย์, ใช้แบบประเมินที่ครูยืนยัน, จำกัด Rules สำหรับคะแนน, เพิ่มคิวบันทึกถาวร, แยกปี/เทอม และเพิ่มขั้นรอยืนยัน/ปิดผลพร้อม snapshot ดูหลักฐานแบบฟอร์มใน [mapping แบบฟอร์ม 2569](grading-template-mapping-2569.md)

## สิ่งที่ควรแก้ก่อนเพิ่มความสามารถใหม่

### 1. ยกเลิกการรีเซ็ตคะแนนอัตโนมัติระหว่างอ่านข้อมูล — เร่งด่วน

- `src/services/gradeService.ts` ฟังก์ชัน `loadGrades` ตรวจว่ามีนักเรียน ป.1 คนใดได้ปลายภาค 28 และ K ตัวชี้วัดแรก 15 แล้วเรียก `restoreRealP1Grades()`
- เงื่อนไขนี้เกิดกับคะแนนจริงที่ถูกต้องได้ ไม่ได้พิสูจน์ว่าข้อมูลเป็นข้อมูลทดลอง
- ฟังก์ชันคืนค่าชุดตั้งต้นเรียก `saveGrades` ซึ่งเขียน cache และเริ่มส่ง Firebase อีกด้วย
- ควรเปลี่ยนเป็นกระบวนการย้ายข้อมูลที่มีเลขรุ่น ตรวจเงื่อนไขชัดเจน และมีสำเนาก่อนแก้ การเปิดอ่านคะแนนต้องไม่เปลี่ยนคะแนน
- เกณฑ์ผ่าน: กรอกปลายภาค 28 และ K 15 แล้วเปิดสมุดคะแนนซ้ำ คะแนนทุกคนต้องคงเดิม

### 2. แก้การล้างคะแนนและการรวมรายชื่อ — ยืนยันด้วยข้อมูลจำลอง

- `mergeIndicatorForStudent` เลือกค่าครูจากข้อมูลเก่าเมื่อค่าฝั่งใหม่เป็น `undefined` จึงแยกไม่ได้ระหว่าง "ไม่ได้ส่งช่องนี้มา" กับ "ตั้งใจล้างช่องนี้"
- ผลทดลอง: ข้อมูลเก่า `teacherK=15` ข้อมูลใหม่ล้าง `teacherK` และเหลือ `webK=8` เมื่อรวมแล้วกลับเป็น `teacherK=15`
- `mergeRemoteWithLocalGrades` วนเฉพาะรายชื่อฝั่ง remote ทำให้รายการที่มีเฉพาะในเครื่องไม่อยู่ในผลลัพธ์
- ผลทดลอง: remote มีรหัส `remote` ส่วน local มีรหัส `local` ผลรวมเหลือเพียง `remote`
- ควรมีคำสั่งล้างที่ระบุชัดเจนและรุ่นการแก้ไขรายช่อง รวมรายชื่อโดยรหัสนักเรียนถาวร และแยกสถานะย้ายออก/ลบจากการที่ไม่พบในคำตอบของเซิร์ฟเวอร์
- เกณฑ์ผ่าน: ล้างคะแนนแล้ว F5/เปิดอีกเครื่องไม่คืนค่าเก่า นักเรียนใหม่ไม่หลุด และการแก้คนหนึ่งไม่ทับคนอื่น

### 3. จำกัดสิทธิ์อ่านและเขียนคะแนน — เร่งด่วนควบคู่กัน

- `firestore.rules` ที่ `grades/{docId}` ใช้ `allow read: if true` และ `allow write: if baseWrite(30)` ซึ่งไม่ตรวจตัวตนครู
- ต้องตรวจ Rules ที่เผยแพร่จริงก่อนสรุปสถานะระบบออนไลน์
- ควรใช้ Firebase Auth/บทบาทครูสำหรับแก้คะแนน และออกแบบทางบันทึกหลักฐานกิจกรรมของนักเรียนให้ตรวจสอบได้ก่อนนำไปรวมคะแนน
- การเปลี่ยน Rules ต้องทดสอบบัญชีครู นักเรียน และผู้ไม่มีสิทธิ์ รวมถึงการบันทึกคะแนนจากเกม
- อ้างอิง: [Firebase Authentication ใน Firestore Rules](https://firebase.google.com/docs/firestore/security/rules-conditions)

### 4. ให้ครูเห็นผลการบันทึกจริง

- ฟังก์ชันแก้คะแนนหลายตัวเขียน cache แล้วเรียก `void patchStudentGradeInFirebase(...)`
- ฟังก์ชันส่งคะแนนดักความล้มเหลวไว้ใน console โดยไม่ส่งสถานะกลับหน้ากรอก
- ควรมีสถานะรายรายการ: ร่างในเครื่อง → รอส่ง → บันทึกบนเซิร์ฟเวอร์แล้ว → ส่งไม่สำเร็จ พร้อมส่งซ้ำโดยไม่สร้างรายการซ้ำ
- Firestore transaction ล้มเหลวเมื่อออฟไลน์ จึงต้องออกแบบคิวงานและการลองใหม่สำหรับเส้นทางที่ใช้ transaction
- เกณฑ์ผ่าน: ตัดอินเทอร์เน็ตขณะกรอก ปิดเปิดหน้าใหม่ แล้วต่ออินเทอร์เน็ต คะแนนที่รอส่งต้องยังอยู่และมีผลยืนยันจากเซิร์ฟเวอร์
- อ้างอิง: [Firestore transactions](https://firebase.google.com/docs/firestore/manage-data/transactions)

## โครงสร้างที่ควรปรับ

### 5. แยกปีการศึกษาและภาคเรียนในรหัสข้อมูล

- `ACADEMIC_YEAR` กำหนดเป็น `2569` และข้อความมัธยมกำหนดภาคเรียนที่ 1
- `storageKey`, `gradeDocumentId` และรหัสเก็บงานเพิ่มเติมอิงห้อง/วิชา แต่ไม่มีปีและภาคเรียน
- ควรให้สมุดคะแนนมีบริบทปี/ภาคเรียน/ห้อง/วิชาที่ชัดเจน พร้อมนโยบายรวมผลรายปีของประถม
- เกณฑ์ผ่าน: เทอม 1 และเทอม 2 มีคะแนนต่างกันได้ เปิดย้อนหลังแล้วไม่เปลี่ยนไปตามข้อมูลเทอมใหม่

### 6. ทำสูตรและรายงานให้ใช้ข้อกำหนดชุดเดียวกัน

- สูตร `SCORE_WEIGHT` คำนวณ K/P/A เป็น 42/17.5/10.5 จากคะแนนเก็บ 70
- CSV ใน `gradeService.ts` กลับพิมพ์หัวคอลัมน์เป็น 40/20/10 ส่วนตัวส่งออกอีกบริการใช้ 42/17.5/10.5
- ผลจำลองคะแนนเต็มครบ 12 คู่ห้อง/วิชา: คะแนนรวมยังได้ 100 ทั้งหมด แต่ ป.2, ป.6 และ ม.1–ม.3 วิชา cs ได้ P 17.6 และ A 10.4 เพราะปัดเศษแต่ละตัวชี้วัดก่อนรวม
- ควรคำนวณโดยเก็บความละเอียดภายใน ปัดที่จุดรายงานที่กำหนด และสร้างหัวคอลัมน์จากนโยบายเดียวกับสูตร
- คะแนน P ดิบถูกแปลงเป็นระดับก่อนคิดน้ำหนัก เช่น 24 และ 30 อยู่ระดับเดียวกัน ต้องยืนยันนโยบายโรงเรียนว่าจะใช้คะแนนดิบหรือระดับ ไม่เปลี่ยนสูตรย้อนหลังโดยพลการ
- เกณฑ์ผ่าน: หน้าจอ CSV และ ปพ.5 แสดงคะแนนเต็ม/ผลรวมตรงกันทุกห้อง รวมถึงคะแนนใกล้เส้นแบ่งเกรด

### 7. แยกผลประเมินจริงจากค่าที่อนุมานในเอกสารส่งออก

- `gradeExportService.ts` คำนวณสมรรถนะและอ่าน–คิด–เขียนจากคะแนนรวม และคำนวณคุณลักษณะจากสัดส่วน A
- ระบบมี `studentAssessmentService.ts` และข้อมูลที่ครูยืนยัน (`confirmedByTeacher`) อยู่แล้ว
- ควรเชื่อมเอกสารทางการกับแบบประเมินที่ครูยืนยัน หากยังไม่มีให้แสดง "ยังไม่ประเมิน" ส่วนค่าคำนวณช่วยครูควรแสดงเป็นข้อเสนอพร้อมที่มา
- เกณฑ์ผ่าน: เมื่อครูยืนยันผลประเมินต่างจากค่าที่อนุมาน เอกสารต้องใช้ผลที่ครูยืนยันและตรวจย้อนหลังได้

### 8. แยกคะแนนว่างกับศูนย์และเพิ่มขั้นตอนปิดผล

- `computeGrade` คืนเกรดตัวเลขได้แม้ยังไม่ประเมินครบ และ CSV บางเส้นทางแทนคะแนนสอบว่างด้วย 0
- ควรมีสถานะยังไม่ประเมิน/ประเมินแล้ว/รอยืนยัน และแสดงจำนวนช่องที่ยังขาด
- เพิ่มการตรวจความครบถ้วนก่อนปิดผล เก็บสำเนารุ่นผลที่ยืนยันแล้ว และระบุเหตุผลเมื่อเปิดแก้ไขใหม่
- เกณฑ์ผ่าน: นักเรียนที่ยังไม่กรอกคะแนนไม่ถูกนับเป็นผู้ได้ศูนย์หรือไม่ผ่านโดยอัตโนมัติ เอกสารย้อนหลังอ้างอิงรุ่นคะแนนเดิมได้

## ลำดับดำเนินการที่แนะนำ

1. แก้เส้นทางรีเซ็ตระหว่างอ่านข้อมูล การล้างคะแนน การรวมรายชื่อ และเพิ่มกรณีทดสอบที่ทำให้ปัญหาเกิดซ้ำได้ พร้อมตรวจสิทธิ์ฐานข้อมูลที่เผยแพร่จริง
2. ทำการบันทึกพร้อมสถานะยืนยัน ส่งซ้ำเมื่อเครือข่ายกลับมา และใช้รูปแบบกรอกคะแนนเดียวกันทุกประเภท รวมช่องสอบที่ปัจจุบันบันทึกทุก keystroke
3. ทำสูตร/หัวคอลัมน์ให้ตรงกัน แยกข้อมูลยังไม่ครบ และใช้แบบประเมินที่ครูยืนยันในรายงาน
4. ย้ายโครงสร้างให้รองรับปีและภาคเรียน พร้อมตรวจยอดก่อน–หลัง จากนั้นเพิ่มการปิดผล เก็บรุ่น และย้อนดูการแก้ไข

ผลทดสอบเดิมที่ผ่าน 676 รายการไม่ครอบคลุมทุกกรณีข้างต้น โดยเฉพาะการล้างค่าแล้วรวมกับ remote การคงนักเรียนที่มีเฉพาะ local และคะแนนย่อยเต็มในทุกห้อง การตรวจรอบนี้ใช้ probe ชั่วคราวสำหรับฟังก์ชันบริสุทธิ์เท่านั้น แล้วนำไฟล์ probe ออกหลังบันทึกผล ไม่ได้แก้ตรรกะคะแนนในรอบวิเคราะห์นี้
