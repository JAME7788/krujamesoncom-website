# ผลตรวจการเชื่อมคะแนนเกม 9 กันยายน 2569

## สถานะ

ผ่านการตรวจโค้ดและชุดทดสอบอัตโนมัติในเครื่องสำหรับกรณีที่ระบุด้านล่าง ไม่ใช่การรับรองว่าไม่มีบั๊กทุกสถานการณ์ และยังไม่ใช่ผลทดสอบส่งคะแนนบน Vercel/Firebase production ด้วยเครื่องจริงหลายเครื่อง

ไม่ได้แก้คะแนนนักเรียนจริง ไม่สร้างผลการประเมินย้อนหลัง และไม่ได้ push หรือ deploy ในรอบนี้

## สิ่งที่แก้

1. กิจกรรมเกมอ่านและเพิ่มรายการด้วย Firestore transaction จากข้อมูลบนเซิร์ฟเวอร์ ป้องกันข้อมูลใน cache ที่เคยส่งล้มเหลวถูกนับว่าส่งสำเร็จ และกันการเพิ่มกิจกรรมซ้ำเมื่อส่งพร้อมกันหรือคำตอบจากเซิร์ฟเวอร์สูญหาย
2. ส่งซ้ำด้วยข้อมูลผลเดิมสูงสุด 3 ครั้ง เว้น 1 และ 2 วินาที ไม่ลองซ้ำเมื่อสิทธิ์ถูกปฏิเสธหรือค่าคะแนนไม่ถูกต้อง หากยังส่งไม่ได้จะแจ้งล้มเหลว ไม่แสดงว่าสำเร็จ
3. การส่งครบหมายถึงกิจกรรม หลักฐาน และกระดาษเกรดผ่านทั้งหมด หากกระดาษเกรดล้มเหลวจะส่งใหม่ได้แม้ค่าในเครื่องไม่เปลี่ยน
4. `recordGame(score, activityKey, maxScore)` รับคะแนนเต็มจริง ตรวจค่าติดลบ NaN Infinity คะแนนเต็มไม่เป็นบวก และคะแนนเกินเต็มก่อนเขียน
5. เพิ่มคะแนนเต็มจากเกม: Stroop Color 40, PC Builder ตามจำนวนชิ้นส่วนทุกด่าน, Device Match/Safety ตามจำนวนข้อ, Step Sort ตามจำนวนภารกิจ, Kru-Com ตาม XP เต็มของภารกิจ และเกมกระดานที่รายงานสเกล 100 ส่งเต็ม 100 อย่างชัดเจน
6. เกมที่ไม่ได้ส่งคะแนนเต็มเก็บคะแนนดิบโดยไม่สร้างตัวหาร 100 ขึ้นมาเอง ไม่แปลงคะแนนดิบที่ไม่มีฐานประเมินเป็นร้อยละ
7. รหัสหลักฐานเกมแยกวิชา หน่วย และภารกิจ ไม่บันทึกลงตัวชี้วัดที่ไม่ได้เชื่อมกับหน่วยนั้น หลักฐานที่ส่งล้มเหลวไม่ถูกเพิ่มเข้า cache เสมือนเป็นข้อมูลยืนยัน และการเขียนระเบียนใหม่ไม่คงคะแนนเต็มเก่าที่ถูกถอดออก
8. บัญชีครูและผู้เยี่ยมชมไม่ถูกส่งเป็นนักเรียนรับคะแนน การเล่นคู่กรองผู้มีสิทธิ์และป้องกันชื่อคนเดียวกันถูกส่งสองครั้ง เกมที่ไม่ผูกหลักสูตรไม่สร้างกระดาษเกรดเปล่าและไม่แจ้งว่าสำเร็จ
9. ปรับเส้นทางซิงก์ของนักเรียนให้รักษาช่องคะแนนครู คะแนนงานเพิ่มเติม รูบริก หมายเหตุ และคะแนนสอบที่อยู่บนเซิร์ฟเวอร์ ไม่ใช้เวลาเล่นเกมที่ใหม่กว่าไปทับการแก้ไขของครูหรือแถวนักเรียนอื่น
10. Digital City Quest และ Tycoon โหมดออนไลน์บันทึกผลของที่นั่งผู้เล่นเครื่องนั้นเมื่อได้รับสถานะจบจากห้อง ไม่ใช้คะแนนผู้ชนะหรือค่าเฉลี่ยห้องให้ทุกคน และไม่บันทึกจากเกมที่เจ้าของห้องยกเลิก การเล่นร่วมจอเดิมยังเป็นผลกลุ่ม ไม่ใช่หลักฐานแยกรายบุคคลทุกทีม
11. การเลือกหน่วยรองรับชื่อห้องย่อย เช่น ป.4/1 โดยเลือกหลักสูตร p4 แทนการสร้าง gradeId ผิดเป็น p4/1

## เกณฑ์คะแนนที่คงไว้

- คะแนนในเกม/XP ไม่เท่ากับคะแนนเกรดโดยตรง
- P อัตโนมัติยังนับหลักฐานกิจกรรมตามกติกาเดิม กิจกรรมเดียวกันไม่เพิ่ม P ซ้ำ มีน้ำหนักในคาบ/นอกคาบและเพดานตามระบบเดิม
- K ในกระดาษเกรดยังมาจากควิซและกิจกรรมความรู้ที่กำหนดไว้ ไม่เปลี่ยนให้ทุกเกมเป็นข้อสอบหรือเพิ่ม K เต็มโดยอัตโนมัติ
- หลักฐานเกมที่เก็บในโดเมน K/P เป็นข้อมูลประกอบ ไม่ใช่คำสั่งให้เพิ่มคะแนน K/P ตามคะแนนดิบทันที
- เหรียญตัวละครยังเป็นกระเป๋า localStorage ตามระบบเดิม ไม่ใช่คะแนนเกรด และไม่ได้รับรองการกันรางวัลซ้ำข้ามอุปกรณ์ในรอบนี้

## ผลทดสอบ

- `npm test`: 51 ไฟล์ 589 ข้อ ผ่าน
- `npm run qa:games`: 370 checks ผ่าน
- `npm run build`: ผ่าน TypeScript และสร้าง production bundle
- ESLint ไฟล์บริการ hook และส่วนเกมกระดานที่แก้: ผ่าน
- ชุดทดสอบใหม่ 31 ข้อใน `gameScoreConnection`, `gameResultOwnership`, `retryGameSave` และเพิ่มกรณีห้องย่อยใน `gameScoring`

ชุดเชื่อมต่อใช้ progressService, learningEvidenceService และ gradeService จริงร่วมกัน โดยแทนขอบเขต Firestore ด้วยเซิร์ฟเวอร์จำลองในหน่วยความจำ ไม่ส่งเครือข่ายหรือข้อมูลจริง ทดสอบ:

- 20/40 ไปถึงหลักฐาน และกิจกรรมไปถึง P ในแถวกระดาษเกรด
- คะแนนดิบ 2,500 ไม่มีคะแนนเต็มสมมติ
- ข้อมูลคะแนนผิดรูปแบบถูกปฏิเสธก่อนเขียน
- หลุดก่อนเขียน หลุดหลัง commit แต่ก่อนรับคำยืนยัน ส่งหลักฐานไม่สำเร็จ และส่งกระดาษเกรดไม่สำเร็จ
- การเปิดหน้าใหม่โดย cache ว่างไม่เพิ่มกิจกรรมซ้ำ และกิจกรรมสองรายการที่เข้าพร้อมกันไม่ทำรายการใดหายในการจำลอง
- วิชา cs/dt มีหลักฐานแยกกันและมีตัวชี้วัดตรงหน่วย
- บัญชี admin/external ไม่ถูกบันทึก บัญชีนักเรียนซ้ำในโหมดคู่ถูกนับครั้งเดียว
- เกมไม่มีหน่วยเป้าหมายไม่เขียนคะแนน และผู้ทดลองที่เป็นคู่ไม่ถูกนับเป็นนักเรียน
- การซิงก์นักเรียนไม่ทับคะแนน/หมายเหตุครู หรือแถวของเพื่อน
- การเลือกผลออนไลน์ใช้ที่นั่งตัวเอง ไม่เลือกผู้ชนะ และไม่เลือกผลที่ยังไม่จบหรือถูกยกเลิก
- ลองส่งใหม่แบบจำกัดจำนวนครั้งและหยุดเมื่อไม่มีสิทธิ์

## ข้อจำกัดและขั้นตรวจบนระบบจริง

1. ไม่มีคิวคะแนนถาวรแบบ offline-first: หากปิดหน้า/รีเฟรชก่อนส่งสำเร็จ ข้อมูลที่ยังไม่ยืนยันอาจสูญหาย ต้องกลับมาเล่นใหม่ การลองส่งซ้ำอัตโนมัติทำในหน้าที่ยังเปิดอยู่เท่านั้น
2. การทดสอบจำลองไม่ยืนยัน Firebase rules, เครือข่ายโรงเรียน หรือสิทธิ์ของบัญชีจริง ต้องทดสอบบัญชีนักเรียนทดสอบแยกจาก roster จริงบนสภาพแวดล้อมทดสอบ และตรวจจากหน้าครูอีกเครื่องก่อนรับรอง production
3. การแก้ครั้งนี้มีผลกับรายการที่ส่งใหม่ ไม่ได้ซ่อมหลักฐานเก่าที่เคยใช้คะแนนเต็ม 100 หรือเคยถูกทับข้ามวิชา ต้องตรวจต้นทางก่อนแก้ข้อมูลย้อนหลัง ห้ามอนุมานคะแนนที่สูญหาย
4. ยังไม่ได้จำลองผู้เล่นออนไลน์หลุด ออกจากห้อง และกลับเข้าห้องทุกลำดับ การเลือกเจ้าของผลยึดลำดับที่นั่งเดียวกับระบบห้องเดิม
5. ตรวจการเลือกหลักสูตรห้องย่อยแล้ว แต่ไม่ได้ยืนยันกระบวนการ roster/เกรดของโรงเรียนที่มีหลายห้องย่อยแบบ end-to-end

เกณฑ์ผ่านบนระบบจริงที่เหลือ: จบเกมด้วยบัญชีทดสอบ 2 บัญชีที่ได้คะแนนต่างกัน เปิดหน้าครูอีกเครื่องตรวจคะแนนเต็มและเจ้าของผล ตัดเน็ตแล้วต่อกลับ ส่งซ้ำและรีเฟรชตรวจจำนวนหลักฐาน เปิดสองวิชาตรวจไม่มีข้อมูลทับกัน และยืนยันว่าคะแนนครูเดิมไม่เปลี่ยน
