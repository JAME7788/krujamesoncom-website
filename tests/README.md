# ระบบทดสอบอัตโนมัติ — คู่มือและโจทย์งานสำหรับ Agent ทดสอบ (QA)

## ทำไมต้องมี

เว็บนี้ **คำนวณเกรดจริงของนักเรียนกว่า 200 คน** (คะแนน K/P/A) จากโค้ดกว่า 29,000 บรรทัด
ก่อนหน้านี้ไม่มีเทสต์เลย และเคยพบบั๊กระบบคะแนน 3 จุดจากการไล่อ่านโค้ดด้วยมือ เช่น

- เด็กเล่นเกมเดิมซ้ำ ๆ แล้วได้คะแนน P เพิ่มเรื่อย ๆ (ระบบกันซ้ำพัง)
- เสียงฉลอง + confetti เด้งตอนเด็ก **ตอบผิด**
- คะแนนที่บันทึกเป็น 0 เสมอ

บั๊กแบบนี้ไม่ทำให้เว็บพัง จึงไม่มีใครสังเกต แต่กระทบผลการเรียนของเด็กโดยตรง
**หน้าที่ของระบบทดสอบคือจับบั๊กเงียบแบบนี้ให้ได้ก่อนถึงมือนักเรียน**

## วิธีรัน

```bash
npm test          # เทสต์ตรรกะ (เร็ว ~2 วินาที) — รันได้ตลอด
npm run test:watch # รันค้างไว้ระหว่างแก้โค้ด

# Smoke test ด้วยเบราว์เซอร์จริง (ต้อง build ก่อน)
npm run build
npx serve -s dist -l 5173     # เปิดอีกหน้าต่างค้างไว้
npm run qa:smoke              # เปิดทุกหน้า + ทุกเกม เช็ค error
```

**ก่อน deploy ทุกครั้งต้องผ่านทั้ง 3 อย่าง:** `npm test` · `npm run build` · `npm run qa:smoke`

## 🚧 งานที่ควรทำต่อ (เรียงตามความสำคัญ)

### 1. เทสต์การคำนวณเกรด K/P/A — **สำคัญที่สุด**
`src/services/gradeService.ts` (1,854 บรรทัด) ยังไม่มีเทสต์เลย ทั้งที่เป็นตัวตัดสินเกรด
ต้องครอบคลุม:
- P ต้องไม่เกิน 30 คะแนน (`PRACTICE_MAX_SCORE`) ไม่ว่าทำกิจกรรมเยอะแค่ไหน
- กิจกรรม **ในคาบ** ได้คะแนนเต็ม · **นอกคาบ** ได้ 40%
- K ต้องไม่ทับคะแนนที่ครูกรอกเอง (`teacherK`) — เคสนี้สำคัญมาก ถ้าพังครูจะเสียงานที่กรอกไว้
- A: เข้าเรียนในคาบ ≥ 2 วันต่างกัน + องค์ประกอบอื่นต้องถูก cap
- คำถามในห้อง 3D ต้องมีน้ำหนักไม่เกิน 50% ของ K

### 2. เทสต์ระบบบันทึกความก้าวหน้า
`src/services/progressService.ts` — โดยเฉพาะ `trackMediaClick`
- กิจกรรมเดิมต้องไม่ถูกนับซ้ำ (ใช้ `dedupKey`)
- `trackWorldMissionEvidence` ต้องเคารพเพดาน (สไลด์ 20 / คำถาม 10 / เกม 4 / ผลงาน 3)
- ต้อง mock Firebase (`src/services/firebase.ts`) เพื่อไม่ให้เขียนฐานข้อมูลจริง

### 3. เทสต์เนื้อหาหลักสูตร
- ทุกหน่วยใน `curriculum.ts` มีหัวข้อและตัวชี้วัดครบ
- ตัวชี้วัดที่อ้างถึง (`indicators: [0,1]`) ต้องมีอยู่จริง ไม่ชี้ไปที่ว่าง

### 4. เทสต์การเล่นเกมจนจบ (E2E)
ขยาย `qa-smoke.mjs` ให้เล่นเกมจนจบจริง แล้วตรวจว่าได้คะแนน — ตอนนี้แค่เช็คว่าเปิดได้

## กติกาสำคัญ

### ✅ เทสต์ต้องพิสูจน์ได้ว่าจับบั๊กจริง
เทสต์ที่ผ่านตลอดโดยไม่เคยจับอะไรได้ = ไร้ค่า **ทุกครั้งที่เขียนเทสต์ใหม่ ให้ลองแกล้งใส่บั๊กแล้วดูว่าเทสต์ FAIL จริงไหม** แล้วค่อยคืนโค้ดเดิม

ตัวอย่างที่ทำไว้แล้ว: แกล้งเอาคะแนนใส่กลับเข้าไปในคีย์กันซ้ำ → เทสต์ FAIL ทันที ✓

### ✅ ขอบเขตไฟล์ — ห้ามข้าม
โปรเจกต์นี้มีหลาย agent ทำงานพร้อมกัน และเคยชนกันจน commit แยกไม่ได้

| Agent นี้เป็นเจ้าของ | ห้ามแก้เด็ดขาด |
|---|---|
| `tests/**` | `src/**` ทั้งหมด |
| `scripts/qa-*.mjs` | `src/pages/VirtualClassroom.*` (มี agent อื่นทำอยู่) |
| `vitest.config.ts` | `src/services/**` |

**ถ้าเทสต์เจอบั๊กในโค้ด `src/` → อย่าแก้เอง ให้รายงานพร้อมเทสต์ที่พิสูจน์บั๊กนั้น** แล้วให้เจ้าของไฟล์แก้
(ยกเว้นครูสั่งให้แก้โดยตรง)

### ✅ ห้ามเทสต์แตะข้อมูลจริง
ความก้าวหน้านักเรียนเก็บบน Firebase อย่างเดียว ไม่มีสำเนาในเครื่อง
**ห้ามให้เทสต์เขียน Firebase จริง** — ต้อง mock เสมอ ไม่งั้นข้อมูลนักเรียนจะเพี้ยน
